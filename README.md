# HR Service — ระบบรับข้อร้องเรียนคนขับและบริการพนักงาน

Frontend UX/UI ที่รวมสองอย่างเข้าด้วยกัน:

- **ดีไซน์** จาก Claude Design (`HR System.dc.html` + `HR Wireframes.dc.html` แนวทาง 1a + 1b + 1c)
- **กระบวนการทำงานจริง** จากระบบเดิม `mena-next-lb/src/app/driver-complaint`

สร้างด้วย Next.js 16 + Tailwind v4 + daisyUI 5

> ยังเป็น **frontend เท่านั้น** — ข้อมูลทั้งหมดเป็น mock ใน `lib/data.ts`

## เริ่มใช้งาน

```bash
npm install
npm run dev
```

เปิด http://localhost:3000 แล้วเข้าสู่ระบบด้วยบัญชี Google ของบริษัท

## มุมมองเดียว

| เส้นทาง | ใครใช้ | อะไรอยู่ในนั้น |
|---|---|---|

## วงจรชีวิตเคส

```
คนขับแจ้ง ──► เปิดเคส ──► มอบผู้รับผิดชอบแล้ว ──► รออนุมัติ ──► รอปิดเคส ──► ปิดเคสแล้ว
                  │                │                  │
           ERZONE มอบ PIC   PIC กรอกแผนแก้ไข   ผู้จัดการอนุมัติ 2 ระดับ
                                              (ปฏิเสธ → กลับไปแก้แผน)
```

หน้าเคสเรียงตามคำถามในหัวผู้ใช้: **เรื่องอะไร → ถึงไหนแล้ว → ต้องทำอะไร**
โดยแถบความคืบหน้า 5 ขั้นอยู่เต็มความกว้างก่อนฟอร์มเสมอ

**มอบหมายหน่วยงานทำจากตารางเคสได้เลย** — คอลัมน์ “ผู้รับผิดชอบ” มีปุ่ม `+ มอบหมาย`
เลือกหน่วยงานแล้วสถานะขยับเป็น “มอบผู้รับผิดชอบแล้ว” ทันที ไม่ต้องเปิดเคส

คลิกเลขติดตามจะเปิด **modal ขนาดใหญ่ทับตาราง** ที่มีแค่ 2 บล็อก:
*รายละเอียดเคสจาก พจส.* (อ่านอย่างเดียว) และ *กรอกข้อมูล* (ฟอร์ม) —
เห็นทุกช่องตลอด ไม่มีปุ่มเปิด-ปิดแก้ไข และมี **ปุ่มบันทึกที่เดียว** อยู่แถบล่างสุด
พร้อมปุ่มอนุมัติ / ปฏิเสธ / ปิดเคส · ผู้ใช้สังกัด HR/ER แก้ได้ทุกสถานะยกเว้นปิดเคสแล้ว

## หน้าจอทั้งหมด

**HR Service Desk (เดสก์ท็อป)**

- `/desk` — สรุปคิวงาน 5 สถานะ + ตารางเคสพร้อมค้นหา / กรองสถานะ / กรอง PIC / กรองเกิน SLA + **มอบหมายหน่วยงานในตาราง**
- `/desk/cases/[trackingNo]` — modal ใหญ่ทับตาราง: แถบความคืบหน้า (มีบรรทัดบอกงานถัดไป) + รายละเอียดจาก พจส. + ฟอร์มกรอกข้อมูล + ปุ่มบันทึก/อนุมัติ/ปฏิเสธ/ปิดเคส ที่แถบล่าง
- `/desk/employee` — ค้นหาข้อมูลพนักงาน
  (โครงหน้าพร้อม ยังไม่มี endpoint ข้อมูล จึงขึ้น empty state)

> หน้าประกาศ (`/desk/announcements`) และหน้ารายงาน (`/desk/reports`) ถูกถอดออกชั่วคราว
> — โค้ดกราฟและข้อมูลตัวอย่างยังอยู่ใน repo
>
> หน้าจองห้องประชุมและจองรถถูกถอดออก พร้อม mock (`rooms` / `vehicles` / `timeSlots`)
> และ type `Room` / `Vehicle`
>
> แอปมือถือของคนขับ (`app/m/**`, `components/m/**`) ถูกถอดออกทั้งชุด รวมถึง `buildServices()`
> `currentUser` `MobileIdentity` `getMobileIdentity()` และ `getCasesByDriver()`

บน topbar มีปุ่ม **สลับโหมดสว่าง / มืด** (จำค่าไว้ใน localStorage · เริ่มที่โหมดสว่างเสมอ)
และ **กระดิ่งแจ้งเตือน** ที่รวมงานค้างจากข้อมูลจริง — เกิน SLA, รอฉันอนุมัติ
และเคสใหม่ที่ยังไม่มอบหมาย

## ข้อมูลอ้างอิงที่ยกมาจากระบบเดิม

- หน่วยงานผู้รับผิดชอบ (PIC) 7 หน่วยงาน — id ตรงกับ `department_id` เดิม
- ประเภทข้อร้องเรียนย่อยตาม PIC
- ผังสาเหตุหลัก 6 กลุ่ม — PAY / OPS / VEH / SAF / MGT / OTH
- ผู้อนุมัติเฉพาะตำแหน่งระดับ ≥ 4 (Assistant Manager ขึ้นไป)
